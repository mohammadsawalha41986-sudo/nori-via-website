# NORIVA Global — SEO implementation and verification

## Scope and baseline

Repository: `mohammadsawalha41986-sudo/nori-via-website`.
Branch: `claude/new-session-39olxc`; starting commit `fb61eea`.
Official origin: https://norivaglobal.com. Railway is the observed production host.
Next.js 15.5.25 App Router, React 19, Prisma 6/PostgreSQL, CMS-backed server rendering.
The build identifies public routes as dynamic SSR, not CSR-only or prebuilt SSG.
Existing design, photographs, motion, CMS content and published URLs were retained.

The production baseline crawl covered 392 sitemap URLs: 110 service routes,
170 library routes, 52 insight routes, 30 tool routes, 14 work routes and 16 other
public routes, counting both languages. No broken internal destination was found;
a nonexistent service returned HTTP 404. Every sitemap page had a title,
description, one H1 and valid JSON-LD. Thirty pages lacked an explicit absolute
share image; all lacked `en-SA` hreflang. One Arabic service used English SEO
copy, creating a duplicate English title. Dynamic content already includes
service benefits, problems, deliverables, FAQ, related services and CTAs.

## Implemented changes

- Reciprocal `ar-SA`, `en-SA`, existing `ar`/`en`, and Arabic `x-default` on
  localized public pages and sitemap entries. Each language stays self canonical.
- Canonical overrides restricted to the same origin and language; query and
  trailing-slash noise removed. Official HTTP/www configuration normalizes to
  HTTPS non-www. A permanent Next redirect consolidates www requests.
  TLS/DNS and HTTP-to-HTTPS termination remain hosting responsibilities.
- Sitemap respects static CMS pages' noindex settings and canonical aliases;
  includes the existing standalone Arabic `/profile`. Draft, private, admin,
  API, search and preview routes are not sitemap entries.
- Explicit robots exclusions for admin/API/dashboard/login/CMS/private; public
  media remains crawlable. API responses now also carry `X-Robots-Tag`.
- Page-specific metadata retained for Home, About, Services, service details,
  Work, project details, Contact, Insights/articles, Library/resources, Tools,
  start pages, restaurant growth and legal pages. Default descriptions are
  summarized; Arabic ignores a mistakenly English-only SEO title in favor of
  the localized page title. Explicit CMS SEO descriptions remain authoritative.
- Absolute OG/Twitter images have service-specific/section-specific fallbacks.
- Organization and WebSite nodes now appear on every localized public page,
  using the same stable IDs. WebPage nodes were added. Service, BreadcrumbList,
  Article and visible FAQ schemas retained. External CMS logos are resolved
  correctly. Address/contact/social data comes from the public layout, matching
  the footer rather than inventing a location, hours, reviews or results.
- Clear editable homepage H1 defaults and an explanatory bilingual restaurant
  consulting paragraph with direct contact link. Saudi Arabia is the published
  service area; no unverified Riyadh street address or local office was added.
- Hero photographs have meaningful localized alt text; existing responsive
  Next images, AVIF/WebP, reserved aspect ratios, priority hero and lazy lower
  images retained. Font `optional` display prevents late swaps/CLS on slow
  connections. Reveal content is initially visible in server HTML and motion
  only arms below the viewport. Reduced-motion behavior retained.
- Project year and homepage tool text contrast improved without changing the
  logo or accent palette. 404 offers Home, Work, Services and Contact.
- Search Console plus Bing verification supported with real optional env tokens.
- Existing GA4/GTM integration retained and IDs validated before script rendering.
- Optional IndexNow authenticates with `/indexnow-key.txt`, queues only explicit
  changed public URLs after authenticated CMS writes using Next `after`,
  deduplicates, timeouts and logs failure without undoing content saves. Empty or
  invalid key disables it. Deleted service/project/article/resource/tool detail
  URLs are invalidated and notified too. Case-study changes invalidate and
  notify their actual project URL. Scheduled publication still needs the
  publisher to run a save/publish action to emit a notification.
- Published slugs are protected from accidental renaming in CMS saves; draft
  slugs remain editable. No existing URL was renamed. A future deliberate URL
  migration must include an explicit permanent redirect before unlocking it.
- Added regression tests and a read-only full sitemap HTTP verifier, also run in
  CI against a production build. No live admin data was modified during audit.

## Endpoints and environment

- Sitemap: https://norivaglobal.com/sitemap.xml
- Robots: https://norivaglobal.com/robots.txt
- IndexNow key: https://norivaglobal.com/indexnow-key.txt (404 until configured)
- CMS: https://norivaglobal.com/admin/seo and page/service SEO fields already
  support title, description, social image, slug and noindex; no schema migration
  or redundant form fields were necessary.

| Environment variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL=https://norivaglobal.com` | Existing authoritative origin setting |
| `SITE_URL=https://norivaglobal.com` | Optional alias when the existing variable is absent |
| `GOOGLE_SITE_VERIFICATION` | Real Search Console HTML-tag token; optional with DNS verification |
| `BING_SITE_VERIFICATION` | Real Bing `msvalidate.01` token |
| `NEXT_PUBLIC_GA_ID` | Optional real GA4 ID, `G-…` |
| `NEXT_PUBLIC_GTM_ID` | Optional real GTM ID, `GTM-…`; avoid installing GA twice via GTM and direct GA |
| `INDEXNOW_KEY` | 8–128 letters, numbers or hyphens; public proof-of-ownership key |

Both environment examples are updated. Existing database, authentication, SMTP
and storage settings must remain unchanged.

## Verification

Local TypeScript, lint, 172 tests and production build passed. No database
credential for local CMS/browser journeys was provided, so live HTTP and
Lighthouse verification complement the build; they do not claim authenticated
CMS mutation tests have run locally. CI has its own PostgreSQL-backed journeys.

Mobile Lighthouse baseline (one lab run, October 4): Performance 78,
Accessibility 96, Best Practices 100, SEO 100; LCP 1.4 s, CLS 0.220, total blocking
time 140 ms, document response 470 ms. Font swaps caused most measured CLS.
These are laboratory measurements through the execution environment, not CrUX
field data. INP requires real interactions/field data and is not established by
this run. Post-deploy verification will be recorded below.

## Owner steps

1. Verify the domain property in Google Search Console and Bing Webmaster Tools,
   using DNS or the supplied real tokens; submit `/sitemap.xml` to both.
2. Add real analytics IDs if measurement is wanted. Add a real IndexNow key if
   automatic notifications are wanted, redeploy, and check the key endpoint.
3. Create/claim Google Business Profile manually if eligible, using the actual
   business contact data and service area; do not invent a physical office.
4. Monitor indexing, search queries, mobile CWV and conversions. Preparation or
   accepted IndexNow submissions do not guarantee indexing, rankings, rich FAQ
   results or inclusion in AI answers. Current illustrative projects remain
   visibly labeled as illustrations, not client outcomes.

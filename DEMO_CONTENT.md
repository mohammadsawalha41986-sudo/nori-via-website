# Temporary content

The site renders entirely from the database, so an empty database renders an
empty site. `scripts/ensure-content.mjs` fills the gaps — and only the gaps —
so a deployment reads as a finished website that can then be edited in Admin.

## What is real and what is temporary

Temporary, safe to replace or delete:

- **Six projects**, slugs prefixed `sample-`. Their `client` field reads
  "Sample project" precisely so nobody mistakes them for Noriva clients.
- **Four insight articles.** Written by us as genuine editorial, but they are
  placeholder publications, not previously published Noriva work.
- **Five services**, **five process stages**, the **about page** copy and the
  **homepage** copy. These describe capabilities in general terms; nothing in
  them asserts a fact about Noriva's history, clients or results.
- **All imagery in `public/img`**, generated by `scripts/generate_imagery.py`.
  Abstract art direction in the brand palette — not photography of real work.

Deliberately left empty, because inventing them would be fabricating facts:

- **Statistics** — no numbers are claimed anywhere.
- **Testimonials** — none.
- **Project `results`** — the schema says "Only verified, real metrics. Never
  fabricated", and that is honoured.

## Replacing it

Everything above is a database row, so replacement is an Admin action, not a
code change. Upload real photography in Admin → Media and select it on the
project, service or article. Delete the `sample-` projects once real ones exist.

## Re-running the script

    node scripts/ensure-content.mjs --report   # inspect, write nothing
    node scripts/ensure-content.mjs            # fill only what is missing
    node scripts/ensure-content.mjs --admin    # also upsert the admin account
                                               # from ADMIN_EMAIL/ADMIN_PASSWORD

It never updates or deletes an existing row: every write is "create only if
absent", and singleton rows are filled field by field only where still empty.
Running it twice changes nothing the second time. It is wired into the Railway
pre-deploy command, after `prisma migrate deploy`.

# Provisioned content

The site renders entirely from the database, so an empty database renders an
empty site. Two scripts fill the gaps — and only the gaps — so a deployment
reads as a finished website that can then be edited in Admin.

    node scripts/ensure-content.mjs    # catalogue: taxonomy, services, tools, library
    node scripts/content-depth.mjs     # depth: bodies, articles, case studies, SEO, imagery

Both are non-destructive: a field is written only when it is currently empty,
so an edit made in Admin always wins, and running either one twice changes
nothing the second time.

## What is real and what is illustrative

**Illustrative — safe to replace or delete:**

- **Twelve projects**, slugs prefixed `sample-`. Their `client` field reads
  "Sample project" precisely so nobody mistakes them for Noriva clients. All
  are DRAFT and `noindex`, and the six F&B ones say in their own opening line
  that they are illustrations of method rather than client work.
- **Six case studies**, one per F&B engagement above. DRAFT and `noindex`.
  Their outcomes are qualitative only — what became clearer, what became
  decidable — because no verified metric exists for illustrative work. The
  `metrics` field is deliberately empty on every one.
- **Two testimonials**, named "Sample testimonial — replace before publishing".
  Unpublished. No words are attributed to any real person or business.
- **All imagery in `public/img`**, generated by `scripts/generate_imagery.py`.
  Composed abstract light studies in the brand palette — not photography of
  real work, and the alt text says so.

**Real editorial, written for this site:**

- **56 services**, each with its own body, benefits, process and FAQs in Arabic
  and English. 34 published, 22 draft pending the operator's decision on which
  the business currently sells.
- **24 articles**, full-length in both languages. Nothing in them cites a
  client, a benchmark or an industry statistic; where a figure appears it is
  arithmetic inside a worked example and is labelled illustrative.
- **36 library resources** and **10 calculators**.
- **9 homepage questions** — four in the open-questions block and five in the
  FAQ block, in both languages. They answer with method rather than with a
  number, so none of them claims a result. Edit them in Admin → Homepage
  questions; a block an editor has already written is never added to.

**Deliberately left empty, because inventing them would fabricate facts:**

- **Contact details** — email, phone, WhatsApp, address and every social URL.
  These render publicly, and a plausible-looking wrong value is worse than
  none. Fill them in Admin → Settings before launch.
- **Logo, logo mark and favicon** — upload the real artwork in Admin → Media.
- **Statistics** — the three that exist describe the methodology and can be
  checked against this database (ten disciplines, seven practice groups, two
  languages). All three are hidden until an owner publishes them.
- **Resource files** — every library entry is DRAFT until its file is uploaded,
  so the Library never offers a download that does not exist.
- **Project `results`** — the schema says "Only verified, real metrics. Never
  fabricated", and that is honoured.

## Imagery

    python3 scripts/generate_imagery.py            # render anything missing
    python3 scripts/generate_imagery.py --force    # re-render everything

An image that already exists is skipped, so a file replaced deliberately is
never overwritten. Names follow `noriva-<section>-<slug>.webp`; the set is
described by `scripts/visual-manifest.json`, which is rebuilt from the database
with `node scripts/build-visual-manifest.mjs` when new content is added.

Every rendered file is registered in the Media Library with Arabic and English
alt text, so it is manageable from Admin exactly like an upload.

## Replacing it

Everything above is a database row, so replacement is an Admin action, not a
code change. Upload real photography in Admin → Media and select it on the
project, service or article. Delete the `sample-` projects once real ones
exist.

## Re-running the scripts

    node scripts/ensure-content.mjs --report   # inspect, write nothing
    node scripts/ensure-content.mjs            # fill only what is missing
    node scripts/ensure-content.mjs --admin    # also upsert the admin account
                                               # from ADMIN_EMAIL/ADMIN_PASSWORD
    node scripts/content-depth.mjs --report    # inspect, write nothing
    node scripts/content-depth.mjs             # fill only what is missing

Neither updates or deletes an existing row: every write is "create only if
absent", and singleton rows are filled field by field only where still empty.
They are wired into the Railway pre-deploy command, after
`prisma migrate deploy`; `content-depth` runs after `ensure-content`.
